STAGO v2.
ERP zbudowany w 8 tygodni.

Stago Group — kontenery, pawilony stalowe, hale — potrzebował własnego ERP zamiast SaaS. SvelteKit + własny Postgres + Keycloak + bidirectional sync z Lovable. 21 modułów, 5 rund pentestów, content studio dla handlowców. Zbudowany przez 1 osobę. Live na stago.com.pl.

01 · kontekstKlient: producent kontenerów i hal stalowych, który wyrósł z SaaS-a.

Stago Group produkuje kontenery, pawilony stalowe i hale. ERP zaczął jako szybki MVP na Lovable + Supabase — w 4 tygodnie miał CRM, leady, wyceny, faktury i bazowy KSeF. Działało. Po 6-8 tygodniach Lovable zaczął ograniczać: brak elastycznego flowu finansowego, hardcoded VAT, koszty utrzymania, vendor lock-in. Każda customizacja kosztowała tydzień bicia się z platformą.

Decyzja Denisa (owner) i moja: zbudować v2 z własnym backendem, zachować parity z Lovable, mieć kontrolę i bezpieczeństwo. Architektura: SvelteKit + własny Postgres + Keycloak + Cloudflare Tunnel na Proxmoxie VAVO. Lovable zostaje jako master scheduling/sending do cutoveru, v2 jako visibility + cancel + nowy UI + finansowe operacje. Synchronizacja przez HMAC + idempotency edge functions.

02 · stan zastanyCo bolało w Lovable.

Lovable v1 robił swoje, ale dla firmy która zarabia na fakturach, KSeF i poprawnym VAT-cie miał konkretne ograniczenia:

  • Hardcoded VAT 1.23 wszędzie. 23% wbite w kod jako stała. Każda transakcja, każdy dokument, każda wycena. Brak elastyczności na 8%, 5%, 0%, eksport, odwrotne obciążenie. Każda zmiana = bugfix przez Lovable support.
  • Single status type, brak segmentacji KPI. Dashboard pokazywał liczbę leadów. Nie pokazywał: ile na etapie wyceny, ile w ofercie wysłanej, ile w produkcji, ile zafakturowanych. Zarząd musiał liczyć ręcznie.
  • Sales commissions w Excelu. Handlowiec sprzedaje, prowizja liczona ręcznie raz w miesiącu. Błędy regularne, brak audit trail, księgowa traciła 4-6h/mc na weryfikację.
  • Content marketing: ręcznie w Canva. Każdy handlowiec na swoim koncie Canva, każdy partner-instalator prosi o nowe banery do FB/IG, ktoś musi je tworzyć. Wąskie gardło u jednej osoby (tu: Karol).
  • Wszystkie pliki w storage Lovable. Brak audit trailu kto kiedy podmienił PDF wyceny. Koszt rośnie z liczbą leadów.

Dla firmy która żyje z faktur i KSeF, hardcoded 23% w kodzie to nie bug — to architektoniczna wada. — pierwsza diagnoza Lovable v1

03 · chronologiaSześć etapów budowy v2.

Cutover big-bang z Lovable na własny stack = ryzyko utraty danych i kilka dni przestoju. Wybraliśmy podejście wars­twowe: budujemy v2 obok Lovable, synchronizujemy bidirectional, dorzucamy nowe moduły jeden po drugim. Każdy etap = działający kawałek wartości, nie wyłącznie krok techniczny.

01 · 03.2026

Architektura v2 + setup Proxmox VAVO.

SvelteKit 5 frontend, własny Postgres na VM 141, Keycloak jako auth (5 client roles), Cloudflare Tunnel na produkcję. ESLint security plugin + Playwright e2e + Dependabot od dnia zero. Decyzja: v2 = visibility + cancel + finansowe operacje; Lovable zostaje jako master sending do cutoveru.

02 · 04.2026

Phase 1 sync — bidirectional, 500 records.

Mig 028 prod (12 nowych kolumn pending_sequence_steps + processing status + trigger). 3 Edge Functions po stronie Lovable (bulk-export + sync-pull + sync-push) z HMAC + replay protection + LWW + idempotency. v2 widzi pending/sent/cancelled/failed. Cancel z v2 → Lovable cron skip race-safe (recheckBeforeSend). 500 rekordów zsynchronizowanych w pierwszym imporcie.

03 · 04.2026

Wariant A v4 — refactor finansowy.

13 commitów, 4 migracje (033 lead_files.slot, 034 lead_quotes.vat_rate, 035 proforma_settlements, 036 backfill). Eliminacja hardcoded 1.23 — zero w produkcji. Custom VAT per dokument i per wycena. Multi-advance per proforma (Model A: wpłaty na proformie). Walidacje art. 106f. Lead/accounting hero KPI grid 2x3 z segmentacją statusów. Header sums bez podwójnego naliczania.

04 · 04.2026

Sales commissions ledger + auto-trigger.

Tabela sales_commissions z centralnym auto-triggerem na zmianie statusu zlecenia. UI /settings/payouts z combined sales + partner sums. CSV eksport dla księgowej. Wypłaty UI: pending → approved → paid (audit trail). Czas księgowej spadł z 4-6h/mc na ~30 min. Handlowiec widzi swoją prowizję per-lead w Pulpicie. Zero ręcznego liczenia.

05 · 04.2026

Content Studio — handlowiec generuje banery sam.

Admin template manager + partner photo upload + Canva-base overlay pipeline (Sharp, kompresja 89%). 6 wariantów reklam Stago (V1-V6) + QR + Story + Landscape. Handlowiec wgrywa zdjęcie realizacji, wybiera template, generuje gotowy plik PNG/JPG w 3 sekundy zamiast 30 minut w Canva. Wąskie gardło zniknęło. Partnerzy-instalatorzy generują materiały sami przez portal.

06 · 04-05.2026

Custom Keycloak theme + landing brand refresh.

Pełen rebrand login/account screen (logo Stago, kolory, locale auto-close, profile UI, mobile polish). Landing /r/[code] przepisany pod stago-site brand z 6 modelami kontenerów + smooth transition. Google Reviews via Places API (zamiast hardcoded). Won quote → auto-create projekt produkcyjny (parity Lovable lead→zlecenie→projekt flow), w mig 056 rozdzielone od zlecenia księgowego.

07 · 04-05.2026

Pentesty — 5 rund + audit refresh.

Code review + external pen-test sesja #3 + raport findings. Audit refresh 2026-05-06: SVG upload XSS regression fix (sanityzacja), host-header magic-link/PDF fallback fix, redacted handoff secrets w repo, removed public Google API key, npm audit production HIGH=0. Security debt zarządzony, nie odsuwany. Security treated as a build pillar, nie post-hoc QA.

04 · stackCo stoi pod warstwami.

— Frontend
SvelteKit 5 TypeScript Vite ESLint security plugin Playwright e2e
— Backend / DB
Postgres (own, VM 141) Keycloak (5 client roles) Persistent volume (uid 100:101) Sharp (image pipeline) PDF server-side render
— Sync layer
Edge Functions (Lovable) sync-worker (v2) HMAC + replay protection LWW + idempotency Auto-recreate + orphan cleanup
— Infra / hosting
Proxmox VAVO (192.168.3.226) Cloudflare Tunnel stago.com.pl (landing) erp.stago.com.pl (app) CSP frame-ancestors self

Stack jest świadomie dobrany: SvelteKit dla DX i bundle size, Postgres dla operacji finansowych z constraints, Keycloak żeby auth nie był domowej roboty, Cloudflare Tunnel zamiast otwierania portów. Nie ma tu narzędzia "modnego" — każde rozwiązuje konkretny problem produkcyjny i ma plan disaster recovery.

05 · efektCo się zmieniło — mierzalnie.

— VAT
Z hardcoded 1.23 na custom VAT per dokument i per wycena. 23% / 8% / 5% / 0% / eksport — wszystko w UI handlowca, bez deweloperskiego release'u. Walidacje art. 106f wbudowane.
— prowizje
Z 4-6h/mc księgowej na 30 min. Auto-trigger na statusie zlecenia, audit trail, CSV eksport, UI flow pending → approved → paid. Zero ręcznego Excela.
— content
Z 30 min w Canva na 3 sekundy w Content Studio. Handlowiec + partner generują reklamy samodzielnie z 6 templatów (V1-V6 + QR + Story + Landscape). Wąskie gardło zniknęło.
— security
5 rund pentestów + audit refresh. SVG XSS, host-header magic-link, secrets w repo, public API key — wszystko zamknięte. npm audit production HIGH = 0. Security debt zarządzony.

06 · lekcjeTrzy rzeczy które bym zrobił inaczej.

  1. Zacznij od pentest pipeline, nie od features. Pierwsze 5 commitów powinno postawić ESLint security plugin + Playwright e2e auth/RBAC + Dependabot. To dodaje 30 min na start, oszczędza dni później. Pentest sesja #1 wymusiła refactor 4 endpointów — gdyby od początku był e2e, znaleziono by to w PR.
  2. Sync architecture > raw migration. Cutover Lovable → v2 jako big-bang to dni przestoju i ryzyko utraty danych. Bidirectional sync (HMAC + LWW + idempotency) kosztuje 1-2 tygodnie pracy, ale daje prawo do cofnięcia, daje czas na test każdego modułu osobno, daje możliwość ostrego cutoveru kiedy parity jest 100%. Powtórzyłbym ten wzorzec.
  3. Content tooling = sales weapon. Content Studio (handlowiec generuje banery sam, partner też przez portal) wycenił sam siebie w ~3 tygodnie przez self-service materiałów dla 39 użytkowników. To narzędzie do sprzedaży, nie back-office'owy gadżet. W kolejnym ERPu Content Studio idzie do MVP, nie do "nice-to-have phase 2".

Własny ERP vs SaaS = większe ryzyko, większa kontrola. Dla SME 50-300 osób z dev-em na pokładzie i jasnymi procesami często warte. Bez deva — zostań w SaaS. — co rekomenduję klientom

Główna lekcja: Lovable / Supabase / no-code nie są złe — są świetne na prototyp i pierwsze 6-12 miesięcy. Ale gdy firma żyje z faktur, KSeF i poprawnego VAT-u, w pewnym momencie cena elastyczności rośnie szybciej niż cena migracji. Świadoma decyzja kiedy schodzić z SaaS-a to oszczędność miesięcy walki z platformą.

Twój SaaS zaczyna ograniczać firmę?

Audyt operacyjno-technologiczny 7 dni — sprawdzimy razem czy zostać, jak negocjować, czy budować własne. Mapa kosztów (utrzymanie + customizacja + ryzyko vendor lock-in vs własny build), 3 ścieżki ze wskazaniem rekomendowanej, plan 30-60-90 dni. Bez zobowiązań na dalszą współpracę. Cena ustalana po krótkiej rozmowie.
